# ルール: `size/`

## 目的

`size/` ルールはファイル・関数・インターフェースの大きさに上限を置きます。ほかのルールと同じく、チェックを落とすのは、変更が悪くしたものだけです。上限を置くのは、人やエージェントが一度に読み切れる大きさを超えたコードは、全体を理解しないまま変えられやすいからです。

## ルール

| ルール | 測るもの | 既定の上限 |
|---|---|---|
| `size/file-lines` | ソースファイルの行数 | 400 |
| `size/function-lines` | 関数やメソッドの行数（宣言から閉じ括弧まで） | 60 |
| `size/params` | 関数やメソッドの引数の数（レシーバは数えない） | 5 |
| `size/complexity` | 関数やメソッドの循環的複雑度 | 15 |
| `size/interface-methods` | インターフェースのメソッドの数 | 5 |

どれも見つけるルールで、既定で有効です。

- **見つけるもの**: 上限を超えたファイル・関数・インターフェース
- **なぜ困るか**: 上限を超えると、コードは一度に読み切れなくなります。全体を理解しないまま、変更が入ります。
- **直し方**: もともとある切れ目で分けます。例: 手順ごとにヘルパー、関心ごとに型。上限を上げるのは、人が確認する設定の変更です。

循環的複雑度は 1 に `if`、`for`、`case`（`default` は除く）、`&&`、`||` をそれぞれ1ずつ足した数です。各アダプタは自分の言語の分岐をこの数え方に当てはめて数えます。

### 測るもの

測るのは製品のコードだけです。ソースファイルと、その中のシンボルを測ります。テストファイルと生成されたファイルは測りません。テストは事例の表などでもともと長くなります。生成されたコードは、誰も分けられません。

### 悪くなれば後退

違反のアンカーはファイルかシンボルです。そのため、base に既にある違反は、行がどう動いても止めません。

違反は**測った値**も持ちます。head の違反が base のものと照合され、値が大きくなっていれば後退です。例: 80行の関数が90行に伸びると落ち、75行に縮むと通ります。

これは測った値を持つ違反に対するエンジンの一般的な規則で、`size/` が独自にしていることではありません。規則は [engine.ja.md](engine.ja.md) にあります。

## 設定

```yaml
rules:
  size:
    file-lines: 300           # 5つのどれでもよい。省いたキーは既定のまま
    function-lines: 60
    params: 5
    complexity: 15
    interface-methods: 5
```

- 高い上限は低い上限より緩い扱いです。そのため、上限を上げるには人の確認が要ります（終了コード `3`）。下げるときは要りません。
- 上限は head の設定から取り、両方の版に当てます（[configuration.ja.md](configuration.ja.md)）。そのため、上限を下げても、報告されるのは変更が足したものだけです。もともと超えていたものは報告されません。

## 事実

| 事実 | 使い道 |
|---|---|
| `File.Lines`、`File.Role` | `size/file-lines` |
| `Symbol.EndLine`、`Symbol.Params`、`Symbol.Complexity` | 関数とメソッド |
| `Symbol.Kind` = `interface`、`Symbol.Methods` | `size/interface-methods` |

## 自己テストの事例

| ルール | 事例 |
|---|---|
| `size/function-lines` | 新しい長い関数は落ちる · 動いただけの既存の長い関数は通る · 伸びた既存の長い関数は落ちる · 縮んだものは通る · 長いテスト関数は通る |
| `size/file-lines` | 上限を超えて伸びたファイルは落ちる · 生成されたファイルは通る |
| `size/params` | 引数の多すぎる新しい関数は落ちる · 引数が5つなら通る |
| `size/complexity` | 分岐の多すぎる新しい関数は落ちる · 上限ちょうどの関数は通る · `default` は分岐に数えない |
| `size/interface-methods` | 新しい幅の広いインターフェースは落ちる · メソッドが5つのインターフェースは通る |
| （設定） | 下げた上限は新しいコードだけを報告する · 上げた上限は人の確認が要る |

## 不変条件

1. 上限は製品のコードにだけ当てます。テストと生成されたコードは、決して測りません。
2. base にある違反は、変更がそれを大きくしない限り止めません。

## 意図して入れなかったもの

- パスごとの上限。例: フロントエンドのディレクトリには、もっと小さい上限を置く。
- 「論理的な」行を数えること。「論理的な」行とは、コメントや空行を除いた行です。読み手が読むのは、画面上の行です。
