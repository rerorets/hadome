# ルール: `size/`

## 目的

人やエージェントが一度に読み切れる大きさを超えたコードは、全体を理解しないまま変えられやすい。`size/` ルールはファイル・関数・インターフェースに上限を置き、ほかのルールと同じく、変更が悪くしたものだけを落とす。

## ルール

| ルール | 測るもの | 既定の上限 |
|---|---|---|
| `size/file-lines` | ソースファイルの行数 | 400 |
| `size/function-lines` | 関数やメソッドの行数（宣言から閉じ括弧まで） | 60 |
| `size/params` | 関数やメソッドの引数の数（レシーバは数えない） | 5 |
| `size/complexity` | 関数やメソッドの循環的複雑度 | 15 |
| `size/interface-methods` | インターフェースのメソッドの数 | 5 |

どれも見つけるルールで、既定で有効。

- **見つけるもの**: 上限を超えたファイル・関数・インターフェース
- **なぜ困るか**: 上限を超えると、コードは一度に読み切れなくなる。全体を理解しないまま変更が入る
- **直し方**: もともとある切れ目で分ける（手順ごとにヘルパー、関心ごとに型）。上限を上げるのは人が確認する設定の変更だ

循環的複雑度は1に `if`、`for`、`case`（`default` は除く）、`&&`、`||` をそれぞれ1ずつ足したもの。各アダプタは自分の言語の分岐を同じ数え方に写す。

### 測るもの

製品のコードだけ。ソースファイルとその中のシンボルを測る。テストファイルと生成されたファイルは測らない。テストはもともと長い（事例の表）し、生成されたコードは誰も分けられない。

### 悪くなれば後退

見つかったもののアンカーはファイルかシンボルなので、base に既にある違反は、行がどう動いても止めない。見つかったものは**測った値**も持つ。head の見つかったものが base のものと照合され、値が大きくなっていれば後退だ。80行の関数が90行に伸びると落ち、75行に縮むと通る。これは測った値を持つ見つかったものに対するエンジンの一般的な規則（[engine.ja.md](engine.ja.md)）で、`size/` が独自にしていることではない。

## 設定

```yaml
rules:
  size:
    file-lines: 300           # 5つのどれでもよい。省いたキーは既定のまま
    function-lines: 60
    params: 5
    complexity: 15
    interface-methods: 5
```

高い上限は低い上限より緩いので、上限を上げるには人の確認が要り（終了コード `3`）、下げるときは要らない。上限は head の設定から取り、両方の版に当てる（[configuration.ja.md](configuration.ja.md)）。なので上限を下げても、報告されるのは変更が足したものだけで、もともと超えていたものは報告されない。

## 事実

| 事実 | 使い道 |
|---|---|
| `File.Lines`、`File.Role` | `size/file-lines` |
| `Symbol.EndLine`、`Symbol.Params`、`Symbol.Complexity` | 関数とメソッド |
| `Symbol.Kind` = `interface`、`Symbol.Methods` | `size/interface-methods` |

## 自己テストの事例

| ルール | 事例 |
|---|---|
| `size/function-lines` | 新しい長い関数は落ちる · 動いただけの既存の長い関数は通る · 伸びた既存の長い関数は落ちる · 縮んだものは通る · 長いテスト関数は通る |
| `size/file-lines` | 上限を超えて伸びたファイルは落ちる · 生成されたファイルは通る |
| `size/params` | 引数の多すぎる新しい関数は落ちる · 引数が5つなら通る |
| `size/complexity` | 分岐の多すぎる新しい関数は落ちる · 上限ちょうどの関数は通る · `default` は分岐に数えない |
| `size/interface-methods` | 新しい幅の広いインターフェースは落ちる · メソッドが5つのインターフェースは通る |
| （設定） | 下げた上限は新しいコードだけを報告する · 上げた上限は人の確認が要る |

## 不変条件

1. 上限は製品のコードにだけ当てる。テストと生成されたコードは決して測らない
2. base にある違反は、変更がそれを大きくしない限り止めない

## 意図して入れなかったもの

- パスごとの上限（フロントエンドのディレクトリにはもっと小さい上限、など）
- 「論理的な」行（コメントや空行を除く）を数えること。読み手が読むのは画面上の行だ
