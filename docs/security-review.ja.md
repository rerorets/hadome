# セキュリティレビュー

hadome のセキュリティレビューの記録です。守るものと信頼の境界は[セキュリティの保証](assurance-case.ja.md)にあり、レビューはその主張がコードと合っているかを確かめます。

## 2026年11月のレビュー

| 項目 | 中身 |
|---|---|
| 時期 | 2026-11-20〜2026-11-21 |
| 対象 | 0.10.1 の時点の main。見つけたものは 0.11.0 で直した |
| 行った人 | メンテナ（rerorets）。AI エージェント（Claude Code）でコードをたどり、指摘はどれも手元で再現してから採った |
| 攻撃者が操るもの | プルリクエストの中身すべて。ファイル、ファイル名、`.hadome.yml`、シンボリックリンク、例外の理由 |
| 信頼するもの | 基準のブランチの中身と設定、メンテナ、GitHub と配布先のレジストリ |

### 見方

- [セキュリティの保証](assurance-case.ja.md)の脅威ごとに、対策に書いたことをコードが実際にしているかを読みました。
- 攻撃者が操る入力から、hadome が読む、実行する、書く、出力するの 4 つの経路をたどりました。
- 再現できたものだけを指摘にしました。

### 見つかったものと直し方

| 重さ | 見つかったもの | 直し方 | PR |
|---|---|---|---|
| 中 | プルリクエストの `.hadome.yml` に足した `gates` のコマンドを、人が確かめる前に `hadome check` が実行していた | 基準のブランチの設定に同じ `id` と同じ `run` があるゲートだけを実行する。それ以外は実行せず、`config/gate-not-run` として終了コード `3` で人に回す | #257 |
| 中 | `--head REV` のとき、改行を含むファイル名で `git cat-file --batch` の応答がずれ、違反のあるファイルを別の中身として読んで見逃した | git には物の ID だけを渡し、どの応答も頼んだ物かを確かめる。応答が欠けたら終了コード `2` で止まる | #263 |
| 低 | `extends` やシンボリックリンクを使うと、リポジトリの外のファイルを読ませられた。設定の検証のエラーには値の一部が出て、CI のログに載りえた | シンボリックリンクはたどらず、行き先のパスの文字列として読む。`extends` は base の設定が並べたものだけを読む。共有の設定のエラーには値を出さない | #263 |
| 低 | `/dev/zero` へのシンボリックリンクや FIFO を置くと、メモリを使い切るまで読み続けた | ふつうのファイルだけを読む。128 MiB を超えるファイルは読まずに人に回し、1 MiB を超える設定ファイルでは止まる | #263 |
| 低 | テキストの出力がファイル名や例外の理由をそのまま出すので、端末の制御文字や Actions のコマンド（`::error` など）を差し込めた | 制御文字を含む値は引用符で囲んでエスケープする。CI の例は、警告のコマンドと表のセルに入れる値をエスケープする | #253 |
| 低 | リリースのジョブの checkout が、git の資格情報を `.git/config` に残していた（悪用の経路は見つかっていない） | このリポジトリを checkout するときは `persist-credentials: false` にする | #256 |

### 問題が見つからなかったもの

- 通信: hadome は通信しません。
- コマンドの実行: シェルを通さず、引数を分けて渡します。git に渡すリビジョンの前には `--end-of-options` を置きます（#263 で足した）。
- 配布物: パッケージにはチェックサムと署名があり、リリースのワークフローの権限は必要なものだけです。
- 秘密: リポジトリとワークフローに、秘密の値は入っていません。

### 直した文書

[セキュリティの保証](assurance-case.ja.md)と [SECURITY.md](../SECURITY.ja.md) には、レビューの時点のコードと合わない主張が 3 つありました。どれも上の修正に合わせて直しました。

- `hadome check` はリポジトリのコードを実行しない
- 指定したリポジトリだけを読む
- シンボリックリンクを通して書かない
